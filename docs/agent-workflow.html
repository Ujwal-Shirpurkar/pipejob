Agent Overview

What PipeJob Does

🎯 Product View

  • Discovers job listings from Indeed & Stepstone via Playwright scraping
  • Scores each job against your master CV using Claude Sonnet 4 (0–100 match)
  • Generates a tailored CV and cover letter as PDF per job
  • Auto-fills application forms and uploads files via browser automation
  • Enforces 5 applications/day rate limit via Redis
  • Real-time dashboard with SSE live feed for all status changes
  • Company reference dataset: 40 German tech companies pre-seeded

Human in the loop: Triggering discovery, deciding which jobs to analyse/skip, reviewing generated PDFs before applying. n8n adds an optional human-approval checkpoint before submission.

⚙️ Technical Stack

  • Discovery: Playwright + Stealth, Indeed CSS selectors + Stepstone API interception. Dynamic location parameter.
  • Analysis: Claude Sonnet 4 — match score, keywords, tailored summary, cover letter draft. Full JDAnalysis now persisted to SQLite.
  • PDF Generation (NEW): HTML templates rendered to PDF via Playwright page.pdf(). No DOCX library needed. Professional layout with keyword highlighting.
  • Companies DB (NEW): SQLite companies table with 40 seeded German tech companies. Sector/city/hiring metadata.
  • n8n Webhooks (NEW): 5 integration endpoints for orchestration — trigger discovery, poll pending, approve apply, push status updates, get summary.
  • Rate limiting: Redis-backed 24h rolling window. Both middleware AND in-handler check now correct.

New

HTML → PDF Document Generation

Replaced DOCX library with Playwright-based PDF rendering.

How It Works

  1. buildCVHtml(masterCV, analysis) builds HTML string from template
  2. Skills matching requiredKeywords are styled with a blue highlight badge
  3. Experience bullets use tailoredBullets[company] when available
  4. Playwright opens the HTML via page.setContent()
  5. page.pdf({ format: 'A4', printBackground: true }) renders to buffer
  6. Saved as outputs/{jobId}/cv.pdf and cover-letter.pdf
  7. Download route detects PDF first, falls back to legacy DOCX if needed

Why This Is Better Than DOCX

  • CSS is easier to iterate on than docx paragraph/run objects
  • Visual preview: open any .html in browser before generating PDF
  • Print-media CSS (@page, @media print) gives precise layout control
  • Playwright already installed — no new dependency
  • PDFs are universally readable, no Word required
  • Keyword highlighting (blue badges) is trivially done in CSS
  • Template files: server/src/services/documents/templates/cv.ts

German Company Reference System

A curated, maintainable foundation — not a complete GmbH registry.

⚠️ Scope Limitation — Honest Assessment

Germany has ~3.7 million GmbHs. A complete registry is NOT feasible to maintain in-repo. This system provides a practical curated reference of ~40 German tech companies that are actively hiring, as a starting foundation. For full-scale data acquisition, see the "Future Data Strategy" section below.

What's Implemented

  • SQLite companies table with full schema
  • 40 German tech companies pre-seeded (SAP, Zalando, N26, Celonis, etc.)
  • Fields: name, sector, city, state, size_range, is_actively_hiring, hiring_sources, source_confidence
  • Auto-seed on first server start (idempotent)
  • GET /api/companies with sector/hiring/limit filters
  • POST /api/companies to add/update entries
  • Migration-safe: works with existing databases

Schema

companies (
  id             TEXT PRIMARY KEY
  name           TEXT
  name_normalized TEXT (indexed)
  website        TEXT
  linkedin_url   TEXT
  sector         TEXT (indexed)
  city / state   TEXT
  country        TEXT DEFAULT 'DE'
  size_range     TEXT
  is_actively_hiring INT (indexed)
  hiring_sources TEXT (JSON array)
  notes          TEXT
  source         TEXT ('seed'|'manual'|'scraped')
  source_confidence TEXT ('high'|'medium'|'low')
  created_at / updated_at TEXT
)

n8n Integration Workflow

PipeJob as an n8n-orchestrated agent — webhook contract, boundaries, and human-in-the-loop checkpoints.

Integration Boundaries

PipeJob handles the execution. n8n handles the orchestration.

Authentication

Set WEBHOOK_SECRET in server/.env. All n8n requests must include:

Header: X-Webhook-Secret: your-secret-here

In development with empty WEBHOOK_SECRET, auth is skipped automatically. In production (NODE_ENV=production), the secret is required.

In n8n, add a Header Auth credential with name X-Webhook-Secret and attach it to each HTTP Request node pointing to PipeJob.

n8n Workflow Steps

⏰

1. Schedule Trigger (n8n) — every 6 hours

n8n fires the workflow on a schedule. No PipeJob involvement yet.

↓
🔍

2. POST /api/webhooks/n8n/discover

Body: { keywords, sources, location }. PipeJob runs Playwright scraper, inserts jobs to DB, returns { discovered, ids }.

↓
📋

3. GET /api/webhooks/n8n/pending-analysis

Returns all 'discovered' jobs with their analyseUrl. n8n iterates and fires POST to each analyseUrl.

↓
🤖

4. POST /api/jobs/:id/analyse (loop for each job)

Claude analyses each JD. Status becomes 'analysed'. Match score and full analysis stored in SQLite.

↓
📄

5. POST /api/jobs/:id/generate (loop, only for score ≥ 60)

n8n can filter by matchScore before triggering generation. PDFs created in outputs/{jobId}/.

↓
👤

6. GET /api/webhooks/n8n/pending-review → n8n Wait node

Human-in-the-loop checkpoint. n8n sends a Slack/email message with job title, company, matchScore, and dashboard link. Workflow pauses. Human opens PipeJob dashboard, reviews PDF, then responds to n8n (approve/skip).

↓
✅

7. POST /api/webhooks/n8n/approve-apply

Body: { jobId, approvedBy }. PipeJob triggers apply internally, respects rate limit. Returns apply result.

↓
📊

8. GET /api/webhooks/n8n/status-summary → Slack notification

n8n fetches daily summary (total, byStatus, recentApplied) and sends to Slack or email as a digest.

Webhook Endpoints Reference

MethodPathPurpose

POST/api/webhooks/n8n/status-updatePush status change to PipeJob

Error & Retry Strategy (n8n side)

  • Wrap each HTTP Request node in a Try/Catch Error workflow
  • If discover fails → retry after 30min with exponential backoff
  • If analyse fails → mark job as 'error' via PATCH /api/jobs/:id/status, notify, skip
  • If apply hits 429 → read retryAfter from response, schedule retry with n8n's Wait node
  • Human review timeout → auto-skip after 24h with POST /api/webhooks/n8n/status-update { status: "skipped" }

Bugs Fixed

All Bugs Fixed in Phase 1 & 2

✅ FIXED (Phase 1): analysis_json never persisted to DB

Added analysis_json column to applications table. saveAnalysis() exported from schema.ts. Called in /analyse route. rowToApplication() now restores full JDAnalysis from DB. Server restarts no longer break the generate flow.

✅ FIXED (Phase 1): checkDailyLimit() called without await

Changed if (!checkDailyLimit()) to if (!await checkDailyLimit()) in jobs.ts:151. The in-handler rate limit check now actually evaluates the resolved boolean.

✅ FIXED (Phase 2): discoverJobs() location field was silently dropped

client/src/api/client.ts sent location; backend destructured only { keywords, sources }. Now backend accepts location? and passes it to scrapeJobs(). Scraper default remains 'Deutschland'.

✅ FIXED (Phase 2): No validation on POST /api/cv — could corrupt master-cv.json

Added Zod schema validation (MasterCVSchema) to cv.ts. Invalid bodies return 400 with field-level errors. master-cv.json is only written on valid payloads.

✅ FIXED (Phase 2): Discover UI was completely missing from the frontend

Dashboard.tsx now has a full Discover panel: keyword tag input, location field, source checkboxes, Discover button with loading state, result count, and error feedback.

✅ FIXED (Phase 2): Location hardcoded to 'Deutschland' in scraper

scrapeJobs() signature updated to accept optional location parameter. Route passes it through. Default preserved.

⚠️ KNOWN REMAINING ISSUES

Stepstone API interception is fragile — relies on undocumented internal API structure. May stop working without warning after Stepstone updates. No automatic detection of 0-result scraper runs. | Indeed CSS selectors may break on DOM updates. | LinkedIn source declared in types but scraper not implemented — passing "linkedin" to discover silently returns 0 results. | pdf-lib and bull are installed but unused — can be removed. | Playwright browser not always closed on error — may leak processes under heavy failure scenarios.
